## 📊 Resumen Ejecutivo

### **Problema Identificado**
Durante las pruebas de Paroli con Kraken Demo, el sistema falló múltiples veces debido a:
- ❌ Timeouts de API
- ❌ Errores 500 de Cloudflare
- ❌ Pérdida de conexión WebSocket
- ❌ Sin recuperación automática
- ❌ Pérdida de estado al crash

**Resultado**: Sistema no apto para producción 24/7

### **Solución Implementada**
Capa de resiliencia completa con:
- ✅ WebSocket + REST fallback automático
- ✅ Reconexión automática con exponential backoff
- ✅ Circuit breaker pattern
- ✅ Recuperación de estado después de crashes
- ✅ Detección de fills perdidos
- ✅ Health checks periódicos
- ✅ Métricas detalladas

**Resultado**: Sistema robusto listo para producción

### **Flujo de Conexión**

```
┌─────────────────────────────────────────────────────────┐
│                   ConnectionManager                      │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  1. Intenta WebSocket (CCXT Pro)                       │
│     ├─ ✅ Éxito → CONNECTED_WS                         │
│     └─ ❌ Fallo → Intenta REST                         │
│                                                          │
│  2. Fallback a REST (CCXT estándar)                    │
│     ├─ ✅ Éxito → CONNECTED_REST                       │
│     │              └─ Reconexión WS en background       │
│     └─ ❌ Fallo → FAILED                               │
│                                                          │
│  3. Health Checks (cada 60s)                           │
│     └─ Si falla → Reconexión automática                │
│                                                          │
│  4. Circuit Breaker                                     │
│     └─ Demasiados fallos → Pausa reconexiones          │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### **Flujo de Recuperación**

```
┌─────────────────────────────────────────────────────────┐
│                    StateRecovery                         │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  1. Al iniciar sesión                                   │
│     └─ Busca estado guardado en disco                   │
│                                                          │
│  2. Si encuentra estado                                 │
│     ├─ Carga posiciones guardadas                       │
│     ├─ Sincroniza con exchange                          │
│     ├─ Detecta fills perdidos                           │
│     └─ Continúa desde último punto                      │
│                                                          │
│  3. Durante sesión                                      │
│     └─ Auto-guarda estado cada 60s                      │
│                                                          │
│  4. Al cerrar/crash                                     │
│     └─ Estado queda guardado para próxima sesión        │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

## 🔧 ConnectionManager

### **Features Implementadas**

#### **1. WebSocket Primario**
```python
# CCXT Pro para WebSocket (baja latencia)
ws_exchange = ccxtpro.krakenfutures(config)
await ws_exchange.fetch_ticker('BTC/USD')  # < 100ms
```

#### **2. REST Fallback**
```python
# CCXT estándar para REST (alta confiabilidad)
rest_exchange = ccxt.krakenfutures(config)
await rest_exchange.fetch_ticker('BTC/USD')  # < 1s
```

#### **3. Reconexión Automática**
```python
# Exponential backoff
delay = min(base_delay * (2 ** retry_count), max_delay)
# 1s → 2s → 4s → 8s → 16s → 32s → 60s (max)
```

#### **4. Circuit Breaker**
```python
# Estados
CLOSED      # Normal operation
OPEN        # Too many failures (pausa 5min)
HALF_OPEN   # Testing recovery
```

#### **5. Health Checks**
```python
# Cada 60s verifica conexión
async def health_check():
    await exchange.fetch_ticker('BTC/USD')
    # Si falla → reconexión automática
```

#### **2. Recuperación Automática**
```python
# Al iniciar
state = await state_recovery.recover_session("session_id")

if state:
    # Continuar desde último punto
    print(f"Recuperando {len(state.open_positions)} posiciones")
    print(f"Última vela: {state.candles_processed}")
```

#### **3. Detección de Fills Perdidos**
```python
# Compara posiciones guardadas vs reales
saved_positions = [pos1, pos2, pos3]

# Detecta que pos2 cerró durante desconexión
missing_fills = await detect_missing_fills(...)
# → Busca fill de cierre en exchange
# → Agrega a closed_trades
```

#### **4. Sincronización con Exchange**
```python
# Sincroniza estado guardado con realidad
real_positions = await connector.fetch_positions()
real_balance = await connector.fetch_balance()

# Actualiza estado
state.open_positions = real_positions
state.equity = real_balance['total']['USD']
```

## 📊 Casos de Uso

### **Caso 1: Timeout de API**

**Antes (v1.9.1)**:
```
1. Fetch candle → Timeout
2. ❌ Script termina con error
3. ❌ Estado perdido
4. ❌ Posiciones abiertas quedan huérfanas
```

**Después (v2.0)**:
```
1. Fetch candle (WebSocket) → Timeout
2. ⚠️ Fallback automático a REST
3. ✅ Fetch candle (REST) → Éxito
4. ✅ Continúa operando
5. 🔄 Reconexión a WebSocket en background
```

---

### **Caso 2: Error 500 de Exchange**

**Antes (v1.9.1)**:
```
1. Fetch candle → 500 Error
2. ❌ Script termina
3. ❌ Estado perdido
```

**Después (v2.0)**:
```
1. Fetch candle → 500 Error
2. 🔄 Retry con exponential backoff
3. ⏳ Espera 1s → Retry
4. ⏳ Espera 2s → Retry
5. ⏳ Espera 4s → Retry
6. ✅ Éxito en 4to intento
7. ✅ Continúa operando
```

---

### **Caso 3: Crash del Sistema**

**Antes (v1.9.1)**:
```
1. Sistema operando con 5 posiciones abiertas
2. 💥 Crash (power outage, OOM, etc.)
3. ❌ Estado perdido
4. ❌ No sabe qué posiciones tenía
5. ❌ Tiene que empezar de cero
```

**Después (v2.0)**:
```
1. Sistema operando con 5 posiciones abiertas
2. 💾 Auto-guardado cada 60s
3. 💥 Crash
4. 🔄 Reinicio del sistema
5. 📂 Carga estado guardado
6. 🔄 Sincroniza con exchange
7. ✅ Recupera 5 posiciones
8. ✅ Continúa desde último punto
```

---

### **Caso 4: Desconexión Prolongada**

**Antes (v1.9.1)**:
```
1. Sistema operando
2. 📡 Pérdida de internet (30 minutos)
3. ❌ Script termina
4. ❌ No sabe qué pasó durante desconexión
```

**Después (v2.0)**:
```
1. Sistema operando con 3 posiciones
2. 📡 Pérdida de internet
3. 💾 Estado guardado antes de terminar
4. 📡 Internet restaurado
5. 🔄 Reinicio
6. 📂 Carga estado
7. 🔍 Sincroniza con exchange
8. 🔍 Detecta que 1 posición cerró (TP tocado)
9. 📝 Busca fill de cierre en exchange
10. ✅ Registra fill perdido
11. ✅ Continúa con 2 posiciones restantes
```

## 🔧 Configuración Recomendada

### **Producción**
```python
from tables.resilience import ConnectionManager, StateRecovery

# Connection Manager
connection_manager = ConnectionManager(
    exchange_class=ccxtpro.krakenfutures,
    config={
        'apiKey': os.getenv('KRAKEN_API_KEY'),
        'secret': os.getenv('KRAKEN_SECRET'),
        'options': {'defaultType': 'future'}
    },
    max_retries=10,           # Más intentos en producción
    base_delay=2.0,           # Delay inicial más largo
    max_delay=120.0,          # Max 2 minutos entre retries
    circuit_threshold=15,     # Más tolerante a fallos
    circuit_timeout=600.0,    # 10 minutos antes de reintentar
)

# State Recovery
state_recovery = StateRecovery(
    connector=connector,
    state_dir="./state/production",
    auto_save_interval=30.0,  # Guardar cada 30s
)
```
